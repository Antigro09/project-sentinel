# Phase-2 and AGI Dependency Roadmap

## The dependency correction

The project should not jump from a finite memory result directly into real
software engineering and then treat repository familiarity as cross-domain
continual learning. X66 needs context-scoped transfer. That makes a minimal
X65B mandatory, while the strongest optional mathematical formalism for X65B
remains open.

At the same time, high-dimensional world-model work need not wait for every
memory experiment. The safe acceleration is two parallel evidence lines that
rejoin before continual high-dimensional agency.

```text
EXACT / MEMORY LINE
X64 task induction
  -> X65A structured continual memory
  -> X65B-core context-scoped transfer
  -------------------------------┐
                                  │
CONTINUOUS WORLD-MODEL LINE       │
SHWM Scale 0 pipeline             │
  -> Scale 1 representation       │
  -> Scale 2 model contribution   │
  -> Scale 3 verifier contribution│
  -> Scale 4 causal audit         │
  -> Scale 5 environment transfer │
  -------------------------------┘
                 -> Scale 6 continuous continual learning
                 -> Scale 7 X66 GUI/code
                 -> Scale 8 scaling study
```

This parallelism speeds execution while preserving causal attribution.

## X65A exit contract

Before X65B or SHWM Scale 6 consumes X65A, the exact line must have a committed
verdict on:

- forward transfer to unseen compositions;
- retention after interference;
- revision with low collateral damage;
- negative-transfer controls;
- bounded active memory and disclosed archive growth;
- exact restart;
- no future-target leakage;
- reusable new identities/components;
- matched compute/query/retrieval budgets.

A finite summary, replay equivalence, or clean restart alone is insufficient.

## Minimal mandatory X65B-core

X65B-core must demonstrate:

1. reusable semantic/procedural components carry explicit validity context;
2. components learned in one task improve a structurally related but nonidentical
   task;
3. the target composite itself was never stored;
4. transfer disappears under shuffled dependency/provenance edges;
5. a context switch prevents indefinite use of an old convention/mechanic;
6. stale, poisoned, and superficially similar memories do not create large
   negative transfer;
7. revisions remain local unless evidence connects components;
8. all gains survive genuine process restart.

Full sheaves, category theory, or an unrestricted context lattice are optional.
If a finite factor graph and exact scoped posterior pass the gate, use the
simpler mechanism.

## X66 entry contract

X66 remains real software engineering:

- issue description plus unfamiliar repository, never target patch;
- architecture inspection and competing hypotheses;
- test generation/improvement;
- multi-file edits and full-suite execution;
- failure diagnosis and rollback;
- preservation of unrelated behavior;
- persistent reusable repository and cross-repository knowledge.

X66 begins with generated repositories, then unseen open-source repositories,
then contamination-controlled external benchmarks. SWE-bench remains an
external gate, not the development corpus.

X66 may claim continual transfer only if:

- a prior repository's reusable abstraction improves a different repository;
- exact old answers and patches are unavailable;
- reset/shuffle/no-memory controls remove the gain;
- harmful transfer does not increase;
- the same verifier/memory/planning core is used.

## Relationship to historical X66–X73 labels

The historical roadmap remains useful as capability labels. SHWM adds an
architecture scale axis. They map as follows:

| Historical capability | SHWM dependency |
|---|---|
| X65 lifelong memory | X65A + X65B-core; integrated at Scale 6 |
| X66 real software engineering | Scale 7 code stratum after Scale 2–6 gates |
| X67 cross-domain transfer | first tested narrowly at Scale 5, broadly after Scale 7 |
| X68 uncertain evidence | uncertainty and model-inadequacy layer from Scale 1–4 |
| X69 grounded causal world models | core target of Scale 2–5 |
| X70 multimodal grounding | post-Scale-5 multimodal belief milestone |
| X71 long-horizon execution | hierarchical agency after stable model/memory |

The map avoids renumbering historical experiments while correcting dependency
order.

## Post-SHWM architecture milestones

### 1. Multimodal belief state

Text, image/video, audio, GUI/tool output, sensor state, and action history enter
one time-indexed belief state. Tasks require multiple modalities. Modality
dropout, timing shuffle, corruption, and contradiction controls establish each
modality's contribution.

### 2. Causal/counterfactual mechanisms

Represent mechanism identity and change separately from transition noise.
Evaluate forced interventions, policy changes, correlation reversals, and
object/mechanism substitutions.

### 3. Abstraction and few-shot concept formation

Induce objects, relations, events, affordances, mechanisms, and procedures.
An abstraction passes only if it improves grounded prediction/planning on new
instances, composes, transfers across appearance/modality, and is revisable.

### 4. Lifelong multimodal learning

Combine fast nonparametric belief updates, medium-term structured memory, and
slow controlled adapter/world-model updates. Beat replay under matched active
and archive budgets.

### 5. Metacognitive executive

Uncertainty must change behavior among act, ask, observe, test, replan, switch,
abstain, and expand. Compare with always-act, always-ask, confidence-only, and
ensemble-only controls.

### 6. Hierarchical bounded agency

Project goals, subgoals, options, and primitive actions operate at distinct
timescales. The agent monitors progress, recovers, respects authority and
resource budgets, and stops on success or established impossibility.

### 7. Four-domain transfer

Physical/visual, digital/GUI, software, and social/multi-agent domains use one
shared cognitive core with thin adapters. A held-out unrelated domain must
benefit; reset removes the gain.

### 8. Controlled self-improvement

The system diagnoses a bottleneck, proposes a versioned change, implements it
in a sandbox, runs frozen evaluation, attributes gains, preserves rollback, and
rejects evaluator gaming.

### 9. Frozen integrated human-level evaluation

One system is frozen before held-out domains and streams. Evaluate all five
Sentinel acceptance criteria together with human comparisons under the same
observation, action, time, and tool access.

## Advancement falsifiers

Do not advance because:

- a model fits;
- a latent predicts pixels;
- a backbone has broad pretrained knowledge;
- a memory retrieves exact episodes;
- a plan sounds plausible;
- a benchmark average rises while one pillar collapses;
- parameter count increases;
- a final failure can be patched by changing the task generator.

Advance only when the preceding component produces an interval-supported,
ablation-attributed capability gain under its frozen gate.
